# anymap-agent 架构审查报告

- 审查角色：第三方 LLM agent 集成方 + 地图渲染资深工程师
- 审查日期：2026-09-02
- 审查范围：`GOALS.md`、`AGENTS.md`、`docs/*.md`、`docs/adr/*.md`；另对当前工作树目录结构做了只读核对
- 结论等级：需要完成 P0 后，才适合对外承诺 v0.1

## 1. 总体评价

MapLibre、纯函数 core、GeoJSON 状态和 provider 注册表的主方向是正确的，能够形成一个比“agent 临时拼接地图脚本”更可维护的产品骨架。当前方案仍把 CRS 契约、MapLibre 实际渲染验证、provider 能力边界和 HTML 交付安全性留在假设层，第三方 agent 无法仅凭文档可靠地接入。我的立场是：保留总体选型，但在 P0 完成前不接受“RFC 7946 兼容”“像素级重合”“自包含 HTML”和“合规免 key”这些对外承诺。

## 2. 问题清单

### P0（必须改）

#### P0-1：RFC 7946 与 GCJ-02 的线上数据契约相互冲突

- 依据：`GOALS.md:63-69`、`docs/data-model.md:5-9,37-47`、`AGENTS.md:24-29`。
- 问题：文档同时承诺“RFC 7946 FeatureCollection”、默认/缺省坐标为 GCJ-02、并仅在 `properties.anymap.crs` 中声明坐标系。标准 GeoJSON 的经纬度语义是 WGS-84；把 GCJ-02 数值放进看似标准的 GeoJSON，第三方 GIS、agent 工具和通用 validator 会静默产生偏移。缺省按 GCJ-02 还会把“未声明”变成不可检测的高风险猜测；“转换后输出原坐标系标记 + 记录”也没有定义记录落在哪里、谁负责避免二次转换。
- 建议：冻结一个明确的 wire contract。首选是 agent-facing GeoJSON 采用 WGS-84 作为 RFC 7946 兼容的 canonical 格式，进入 AMap 等 provider 前由渲染边界生成不可变的 provider-specific view；若产品必须以 GCJ-02 作为线上默认，则应明确称为“Anymap GeoJSON profile”而不是 RFC 7946 纯格式，并要求外部输入显式声明 CRS，缺省直接拒绝。两种方案都要定义单向 normalize API、转换诊断（`from/to/count/warnings`）、输出 CRS 和重复转换保护，并加入 WGS-84/GCJ-02/境外坐标的 conformance fixtures。

#### P0-2：验证层不能支撑“像素级重合”和交互验收

- 依据：`GOALS.md:102-108,133-135`、`docs/verification.md:5-13,15-35`、`docs/architecture.md:66-74,94-100`。
- 问题：当前 L1/L2 主要验证公式、CRS 互逆和 `ll2px`；这些不能验证 MapLibre 的 source/layer 配置、相机 zoom/center/padding、栅格瓦片的 XYZ 方向、DPR、抗锯齿、label/halo、fitBounds、popup、图层显隐和透明度。用人工标定的线上底图 label 作为 golden 还会受 provider 内容更新影响。因而“数学正确”不等于“浏览器里画对”，也不等于交互正确。
- 建议：把验收拆为三类并分别定义门槛：
  1. core 数学 golden：公式、CRS、bbox 等纯函数；
  2. 浏览器渲染 conformance：固定 MapLibre/browser/DPR/viewport/camera，使用冻结的瓦片 fixture 或本地 mock tile server，验证 source/layer、要素像素锚点和关键交互；
  3. live provider smoke：只做联网可用性、署名和瓦片响应检查，不把线上 label 像素当稳定 CI golden。
  v0.1 至少应有一条可在 CI 运行的浏览器测试；若确实不能运行 WebGL，就下调“像素级”承诺，不能用 core 测试代替渲染测试。

#### P0-3：provider 接口不足以保证坐标、瓦片和合规行为正确

- 依据：`GOALS.md:41-61`、`docs/provider.md:5-42`、`docs/architecture.md:76-92`。
- 问题：`crs + rasterTemplate` 只描述了两个字段，没有描述 XYZ/TMS 行列规则、tileSize、min/max zoom、有效范围、世界拷贝、语言/样式、retina、请求失败策略、缓存/限流、CORS 要求或署名类型。更关键的是，`crs` 是元数据，不会让 MapLibre 自动完成坐标转换；“切换 provider 仅换 source”不能覆盖 BD-09 等不同坐标基准。把四个白名单 id 放进类型联合也不等于四个 provider 已经可用。
- 建议：定义版本化 `ProviderManifest`，至少包含 `id`、坐标变换方向/能力、tile matrix scheme、tileSize、zoom/bounds、URL 生成策略、attribution、网络/密钥策略和健康检查；由 registry 返回能力而不是只返回字符串。provider 转换必须在渲染边界生成新数据，不能改变 GeoJSON 唯一状态。v0.1 的 runtime registry 只暴露已验证的 AMap；其余 provider 只能作为未启用的扩展接口或 fixture，不应让用户选到后才失败。

#### P0-4：v0.1 的 schema、render、CLI 和 golden 交付物没有形成可安装的垂直切片

- 依据：`GOALS.md:69,73-83,124-130`、`docs/data-model.md:84-87`、`docs/agent-integration.md:5-28,83-94`、`docs/architecture.md:27-37`。
- 问题：文档要求 `packages/core/schema/anymap.schema.json`、`packages/render`、`packages/cli`、`tests/golden` 和 CI/demo，但本次只读核对的当前工作树中实际可见的是 `packages/core` 与 examples，尚未见这些 v0.1 交付物。与此同时，文档把 schema 描述为全链路唯一来源，却没有给出可下载 schema、字段约束、错误码或 CLI 的机器可读输出；第三方 agent 因而只能猜测协议。
- 建议：先完成一个能从安装包执行 `validate -> render -> 打开 HTML` 的最小垂直切片，再扩展功能。将 JSON Schema 作为发布物并由它生成/校验 TS 类型；提供固定的错误码、JSON error mode、字段路径、schema/protocol version 和 conformance fixtures。同步补齐 `packages/render`、`packages/cli`、一条 CI、一个浏览器 smoke 和最小 golden；在这些交付物存在前，把 M1 判据改成“设计完成”，不要宣称可用。

#### P0-5：HTML 输出的“自包含”定义与不可信输入安全边界缺失

- 依据：`GOALS.md:75-83`、`docs/architecture.md:30,61,94-100`、`docs/data-model.md:9,15-18`。
- 问题：所谓“自包含 HTML”又依赖 CDN 的 MapLibre 脚本/CSS 和远程 provider 瓦片，不能离线独立打开，且会受 CDN 版本漂移、CSP、`file://` 浏览器策略和网络可用性影响。另一个更严重的设计空白是：GeoJSON 的 `name`、description 和业务属性都来自 agent/用户输入，但没有规定 HTML/JS 序列化、popup 内容、URL 属性和模板插值的信任边界；直接内联或用 `innerHTML` 会把数据变成脚本注入面。
- 建议：二选一并写入契约：要么 bundle 并固定 MapLibre 版本（同时明确瓦片仍需联网），要么改称“可移植 HTML，依赖 CDN/远程瓦片”，并在输出中嵌入网络依赖和版本信息。所有数据使用安全 JSON 序列化并转义 `<` 等脚本边界，popup 使用 `textContent`，外链仅允许 provider manifest 中的 URL；为产物设置明确 CSP，限制可加载脚本/图片/连接来源，并对 feature 数量、字符串长度和坐标范围设上限。

#### P0-6：对 AMap 公开瓦片“合规、同源、免 key”的承诺缺少可审计发布门槛

- 依据：`GOALS.md:31-39`、`docs/provider.md:15-22,44-58`、`docs/architecture.md:64-74`。
- 问题：文档把公开端点直接等同于“境内合规”和“无前端泄漏面”，但没有记录授权/服务条款依据、署名要求、地域限制、跨域可用性、速率/并发限制、稳定性或变更监测。对第三方集成方而言，这既是法律/运营风险，也是页面可能突然无法加载的单点故障；“免 key”不等于可以无限制地把官方端点嵌入公共产物。
- 建议：为每个 provider 建立合规 manifest：来源与条款链接、核验日期、允许用途/地域、attribution 原文、tile 端点版本、CORS/限流假设、联系人或变更监测方式。发布前做人工合规签核和 live preflight；CI 使用 fixture，不依赖线上端点。若这些证据不能固化，就把 AMap 定位为“用户自行确认条款后的示例 provider”，不要把合规作为库的保证。

### P1（应改）

#### P1-1：`ll2px` 只覆盖无旋转、无倾斜的简化视口，API 语义却接近通用投影

- 依据：`docs/data-model.md:49-75`、`docs/adr/ADR-001-ll2px-scale.md:18-36`、`packages/core` 设计位置见 `docs/architecture.md:20-26`。
- 问题：公式仅以中心点和 zoom 计算平面偏移，没有 bearing、pitch、padding、world wrap、相机约束或 MapLibre 的实际 transform；`width/height` 是 CSS 还是物理像素也依赖调用方理解。ADR 的 scale 结论对特定静态图语境有价值，但不能自动推导出与 MapLibre canvas 在所有视口状态下相同。
- 建议：将 API 明确命名为“top-down unrotated viewport projection”，或实现与 MapLibre camera 对齐的 camera transform，并用 CSS viewport + DPR 的单一单位契约测试。由于 PNG/headless 导出已列为 M3，可在 v0.1 保留公式用于数学 fixture，但移除其作为渲染像素验收的暗示。

#### P1-2：CRS 精度和“自动转换”承诺过强，且没有定义诊断模型

- 依据：`docs/data-model.md:37-47`、`docs/verification.md:29-35`、`GOALS.md:63-67`。
- 问题：文档同时写“精度约 1m 内”和 `1e-6` 级互逆；这两个数字的单位、适用区域、纬度边界和算法误差没有区分。对 GCJ-02 的近似反解，固定迭代次数、境外矩形判断和极端输入都会影响结果。自动转换但只“告警记录”也没有规定 agent 如何拿到告警，容易在无人查看时继续渲染。
- 建议：分别定义角度误差、米制误差和 round-trip 误差，按境内/境外/边界样本给出上限；明确这是可视化级近似而非测绘精度。normalize/convert API 返回 `{data, diagnostics}` 或显式 Result，至少带 `inputCrs/outputCrs/transformedFeatureCount/warnings`；对缺失 CRS、NaN、越界和不支持的 BD-09 转换采用 fail-closed，而不是静默推断。

#### P1-3：`sym` 词汇和样式能力没有冻结，agent 生成结果会产生协议漂移

- 依据：`GOALS.md:63-69`、`docs/data-model.md:11-18,77-87`、`docs/architecture.md:94-100`。
- 问题：目标文档使用 `marker`，数据模型使用 `poi`；route 说支持线宽、虚线、箭头，但属性表只定义了颜色；label 的 `dy` 是像素值，却没有定义 zoom/DPR/anchor 语义；area、popup、图层顺序、icon、可见性和未知字段行为也未规范。第三方 agent 会根据自然语言自行发明属性，导致同一 GeoJSON 在不同 renderer 上结果不同。
- 建议：将 `sym` 枚举、几何约束和视觉属性写进 JSON Schema，统一 `poi`/`marker` 的一个名称；给每个样式属性定义单位、默认值、范围、zoom 插值和无效值行为。把渲染器层 ID、排序规则和 popup 字段也纳入可复现契约；业务字段允许扩展，但渲染器只消费版本化的 `sym` 结构。

#### P1-4：CLI 与 agent 协议缺少可编排所需的稳定细节

- 依据：`docs/agent-integration.md:5-28,61-87`、`AGENTS.md:10-19`、`GOALS.md:71-100`。
- 问题：文档中出现 `provider-list` 与 `providers` 两个命令名；内联 JSON 受 shell argv 长度/转义限制；没有 stdin、输出目录、覆盖、网络失败、默认 provider、viewport、locale、JSON 日志等契约。退出码只有粗粒度的 1/2，agent 无法稳定区分 schema、文件、provider 和渲染失败。MCP/HTTP 尚在 M2+，却被放入“四种语义等价调用面”，容易让 v0.1 使用者误以为已可用。
- 建议：v0.1 只承诺 CLI + 文件协议，并定义 `--input -`/stdin、`--output`、`--overwrite`、`--width/height`、`--zoom/fit`、`--json` 和稳定错误码；规范 stdout 只输出机器结果、stderr 输出日志。明确 `providers` 为唯一命令名，`--version` 同时给出 schema/protocol/core/render 版本；将自然语言/MCP/HTTP 标为未来能力，不作为当前验收输入。

#### P1-5：bbox/fitBounds 和几何有效性边界未定义

- 依据：`docs/data-model.md:77-82`、`docs/provider.md:40-42`、`docs/architecture.md:94-99`。
- 问题：外包框对空集合虽有提及，但没有规定单点/零面积 bbox、跨日期变更线、世界拷贝、极端纬度、Polygon 闭环/洞、无效 LineString 和 zoom clamp 的行为。对 agent 来说，`--fit` 是最常用的入口；一旦 bbox 与 renderer 的相机约束不一致，问题会被误判为 CRS 或像素偏差。
- 建议：把 geometry validation 与 camera fitting 作为同一 conformance 契约：定义 antimeridian 策略、padding、最小 bbox、maxZoom/minZoom、空 FC 的错误码和 Polygon 闭环规则；bbox 结果携带 CRS，并由 render 统一计算最终 camera，而不是让 CLI/core 各自猜测。

#### P1-6：examples 的数据生成不是可复现的验收输入

- 依据：`GOALS.md:110-114`、`docs/architecture.md:33-37`、`docs/provider.md:54-58`、`docs/agent-integration.md:89-94`。
- 问题：示例同时承担真实验收、检索示范和 Pages demo 三种职责，但上游 POI/路线数据会变更，查询“取第一个结果”会改变结果，且没有统一记录查询时间、来源版本、精度、许可和人工复核状态。这样 golden/demo 失败时无法判断是库回归还是数据漂移。
- 建议：将提交到仓库的 examples 变成冻结 fixture，带 `source/provider/retrievedAt/coordinateAccuracy/license` 元数据和人工复核结果；在线 fetch 脚本仅作为 opt-in 工具，不参与 build/CI。demo 验收只消费冻结数据，并另设数据刷新/差异审查流程。

#### P1-7：版本指纹不足以复现渲染结果

- 依据：`GOALS.md:102-108`、`docs/architecture.md:94-100`、`docs/verification.md:37-44`。
- 问题：`provider/zoom/bbox/schemaVer/coreVer` 不能唯一确定页面像素。MapLibre 版本、style/layer 版本、瓦片模板或瓦片内容、center/bearing/pitch/padding、viewport/DPR、locale、数据 hash 和浏览器 renderer 都可能改变结果。
- 建议：将指纹拆成机器可读的 `meta.json` 或 HTML meta 标签，至少包含 canonical input hash、provider manifest hash、tile template hash、maplibre/render/core/schema 版本、完整 camera、viewport/DPR 和 fixture/live 标记；footer 只是展示，不应是唯一取证渠道。

### P2（建议）

#### P2-1：把未来扩展点从 v0.1 的可见 API 中移出

- 依据：`GOALS.md:57-61,124-131`、`docs/provider.md:44-52`、`docs/architecture.md:102-106`、`docs/agent-integration.md:5-12`。
- 建议：MCP、HTTP、Rust/WASM、额外 provider、海外扩展和 PNG headless 导出继续保留设计记录，但不进入 v0.1 的安装包命令、类型联合或用户文档主路径。对外只发布 AMap + core/render/CLI 的真实能力，避免“接口看起来支持、运行时其实未实现”。

#### P2-2：缩小 v0.1 ops 面，优先保证 bbox/validate

- 依据：`docs/data-model.md:77-82`、`docs/architecture.md:20-26`。
- 建议：v0.1 必须保留 `validate`、`bboxOf` 和 render 所需的最小 geometry traversal；`simplifyDP`、长度/面积等信息性算子可延后，或先明确 tolerance/单位/CRS/多环语义。减少无关 API 有助于第三方 agent 形成稳定调用习惯。

#### P2-3：把交互能力改成稳定的 layer/action 契约

- 依据：`GOALS.md:25-29`、`docs/architecture.md:94-100`。
- 建议：为每类 `sym` 分配稳定 layer ID，定义显隐、透明度、点击查询和坐标复制的 DOM/事件语义及无障碍标签；把“工具条存在”升级为可自动化探测的 data attributes 或事件，不依赖人工抽查。

#### P2-4：补充安装、网络和生命周期运维说明

- 依据：`AGENTS.md:10-20,40-42`、`docs/agent-integration.md:83-94`、`docs/provider.md:54-58`。
- 建议：说明 Node/浏览器支持矩阵、包发布方式、CDN/瓦片网络要求、缓存策略、provider 下线处理、schema/core 兼容窗口和安全更新方式。第三方 agent 更需要“失败时怎么恢复”和“什么时候可以放心重试”，而不只是成功命令。

## 3. 对 v0.1 实现范围的增删建议

### 建议增加

1. **一条可安装的最小垂直链路**：`@anymap/core` + `@anymap/render` + CLI + 一个经过核验的 AMap provider + 一个固定 demo；从 GeoJSON 输入到 HTML 产物全程可执行。
2. **正式 schema 与 conformance fixtures**：至少覆盖 WGS-84/GCJ-02 输入、显式/缺失 CRS、四种 geometry 语义、非法坐标、空集合、颜色/label 边界和 provider 不可用错误。
3. **浏览器级 smoke/conformance**：固定浏览器、MapLibre 版本、viewport、DPR 和本地瓦片 fixture，检查图层、fit、popup、透明度和安全序列化；数学 golden 继续保留，但不替代它。
4. **规范化与诊断 API**：将 CRS 转换、校验、相机 fitting、输出 fingerprint 变成稳定的机器可读 API；错误不得只靠中文 stderr 文本。
5. **安全和可移植产物基线**：固定/打包运行时依赖，安全注入 GeoJSON，声明远程瓦片依赖，加入 CSP、输入上限和 provider 请求 allowlist。
6. **冻结 examples 与来源元数据**：在线抓取与静态验收数据分离，保证 CI、Pages 和第三方复现使用同一份 fixture。

### 建议删除或延期

1. 从 v0.1 runtime 中移除未实现的额外 provider、MCP、HTTP、Rust/WASM、PNG/headless 导出和海外扩展；保留为 M2–M4 设计文档即可。
2. 不要把“自然语言任务”列为 v0.1 的输入面；v0.1 由外部 agent 负责把任务转成已验证 GeoJSON，MCP 自然语言工具在 M2 再验收。
3. 不要把 live AMap label 的“像素级重合”作为 CI 或 v0.1 的硬承诺；改为固定 fixture 的渲染一致性，线上 provider 只做可用性/署名 smoke。
4. 若 v0.1 不实现 PNG，保留 `ll2px` 作为受限的 core 数学 API，但删除“它能代表 MapLibre 最终像素”的验收表述。
5. 将“自动缺省 GCJ-02”和“自动转换但只告警”从对外默认行为中删除，改为显式、可追踪、可失败的输入规范化。

## 4. 明确同意与明确反对的设计决策

### 明确同意

- **MapLibre GL JS 作为主渲染内核**：`docs/adr/ADR-003-maplibre-render-core.md:11-18` 的方向正确；底图与业务图层交给同一相机/渲染管线，确实比静态图加手绘覆盖层更容易维护。
- **core 与 renderer 分层**：`docs/architecture.md:5-11,20-32` 的纯 TS 数学层、浏览器渲染层和 CLI 分离，有利于单测、跨语言复核和第三方复用。
- **provider 注册表与合规白名单**：`GOALS.md:31-55`、`docs/provider.md:5-11` 的集中入口、编译期联合类型和运行期检查值得保留；但必须补足 P0-3/P0-6 的能力与证据模型。
- **GeoJSON 作为空间状态、`sym` 表达渲染意图**：`GOALS.md:63-69` 的状态/表现分离适合 agent；前提是先解决 P0-1，并把 schema 冻结。
- **v0.1 先做 CLI + 文件协议，MCP 随后实现**：`GOALS.md:71-100`、`docs/agent-integration.md:5-12` 的渐进式接入顺序合理，能降低首版集成面。
- **将实时导航、离线瓦片库、3D 和商业化鉴权列为非目标**：`GOALS.md:116-122` 有助于守住首版边界。
- **明确记录 scale/DPR 的历史教训**：`docs/adr/ADR-001-ll2px-scale.md:18-36` 作为受限的数学/静态导出契约是有价值的，不应被重新解释成完整渲染证明。

### 明确反对

- **反对把带 GCJ-02 的数据称为普通 RFC 7946，并对缺失 CRS 静默默认**：`docs/data-model.md:5-9,45-47` 会破坏第三方互操作，是最高优先级的协议问题。
- **反对用 core 数学 golden 代替 MapLibre 渲染测试**：`docs/verification.md:5-13,29-35` 不足以证明 `GOALS.md:133-135` 的像素级成功判据。
- **反对认为 provider 只需 `crs + rasterTemplate`、切换只需换 source**：`docs/architecture.md:76-92` 隐藏了 tile matrix、相机、转换、网络和合规能力差异。
- **反对把 CDN 运行时加远程瓦片称为“自包含 HTML”**：`docs/architecture.md:94-100` 必须改成可验证的 portability/network contract。
- **反对把“公开免 key 端点”直接当作无限制、已完成合规审查的生产依赖**：`docs/provider.md:15-22` 需要条款证据、变更监测和失败策略。
- **反对在未实现的情况下对外暴露额外 provider/MCP/HTTP**：`GOALS.md:57-61,124-131` 已把它们放在后续里程碑，应在首版 API 中严格隔离。
- **反对把“30 秒内与真实底图像素级重合”作为没有固定 renderer/provider fixture 的 v0.1 保证**：`GOALS.md:133-135` 应在 P0-2 完成后重新定义为可测的 conformance 指标。
