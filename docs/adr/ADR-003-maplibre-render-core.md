# ADR-003 — 渲染内核定为 MapLibre GL JS（弃用静态图 + 自绘覆盖层方案）

- 状态：**已定案（本 repo 架构基石）**
- 日期：2026-09-02
- 关联：GOALS G1/G3/G5

## 背景

v1–v7 的演进：坐标直接画进静态 PNG（v1–v5，draw-in-PNG，用户无法验证/微调）→ 静态底图 + 手动 SVG 覆盖层（v6，可切换可缩放，但仍要求用户手动对齐）→ 自动对位（v7，发现 label z+1 后对齐）。三阶段每次都把「投影数学、瓦片获取、用户交互、像素标定」搅在一起，出问题只能靠肉眼 + 改参数重渲。

## 决策

本项目渲染内核 = **MapLibre GL JS**：

1. 底图瓦片与矢量数据由同一引擎按同一 zoom 渲染 → 消灭「双 zoom 语义」（ADR-002）与 scale 错乘（ADR-001）两整类偏差。
2. 引擎内置投影/交互/图层管理 → agent 只需给 GeoJSON + 渲染意图，**不再需要也不允许手算像素**。
3. provider 可插拔（合规白名单，docs/provider.md）→ 「任意底图」诉求收敛为「换 RasterTileSource」。
4. 开源免 key，无商业授权与 key 泄漏面。

## 后果

- 正向：像素回路从「每次现场猜」变成「引擎保证 + golden 断言兜底」；标定层只剩数学测试，不需要浏览器。
- 反向：静态图导出（PNG）不再是 provider 原生能力，需 headless 浏览器（M3 评估，文档已注明）；离线场景需自托管瓦片（非目标）。
- 保留项：高德 Web 服务 API（检索/路径规划）仍用于**数据回路**（JSON 坐标），与渲染解耦。

## 验收对应

- 「画得对不对」由 golden 数学断言 + demo 页指纹 + 人工抽查共同保证（docs/verification.md）。
- 「用户手动对齐」从需求清单移除：工具条只保留显隐/缩放/透明度等查看性交互。
